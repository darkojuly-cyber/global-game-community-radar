# Railway 上线步骤

当前已准备 Dockerfile、Railway 健康检查和访问密码保护，但尚未创建任何 Railway 项目或产生网站地址。Railway 的可用额度、试用限制及付费要求以注册时平台展示为准。

## 必需前置条件

1. 注册并登录 https://railway.com/ ，由本人授权连接 GitHub。
2. 先把当前工作区代码提交并推送到选定的 GitHub 仓库。当前源码尚未推送，直接连接远端原始 main 分支不会得到这个应用。
3. 在 Railway 创建项目，添加 PostgreSQL 服务，再添加来自该 GitHub 仓库的应用服务。仓库根目录的 Dockerfile 会用于构建。
4. 在应用服务 Variables 配置：
   - `DATABASE_URL`：引用同项目 PostgreSQL 服务提供的连接变量，不在聊天里发送值。
   - `RADAR_USER`：自定英文登录用户名，不含冒号。
   - `RADAR_PASSWORD`：自定强密码，建议使用密码管理器生成英文/数字/符号，不在聊天里发送值。
   - 可选 `OPENAI_API_KEY`、`YOUTUBE_API_KEY`；无密钥仍可使用 RSS、导入和规则创意。
5. 部署成功后，在应用服务 Networking 生成公共域名。首次打开浏览器会弹出登录框，使用上面的用户名和密码。

容器拒绝在缺少数据库或访问凭据时启动。启动会以 Prisma db push 同步开发阶段 schema，不使用重置或忽略数据丢失警告；已有数据库结构有冲突时应停止并审阅迁移。正式长期生产环境应采用经审阅的迁移和备份流程。

新托管数据库初始为空；云开发环境中的 20 条记录不会自动复制。部署后在「数据源与设置」添加并同步 PH、PK RSS，即可获取当时的真实数据。

## 当前测试边界

本地应用构建和访问保护可测试；没有 Railway 账号授权，未执行远程 Docker 构建、发布或域名生成，不声称网站已经上线。容器监听平台提供的 PORT，使用平台 HTTPS 域名。健康接口不需要登录；其余页面和业务 API 由访问密码保护。

本次额外验证：11 项单元测试与 Next.js 生产构建通过；生产构建的实际请求验证了未登录 401、正确登录 200。完整本地 Docker 构建未完成：当前云环境的容器网络 / 代理信任配置限制了依赖获取，已中止该验证；没有关闭 TLS 校验。Railway 实际构建和域名访问仍需账号授权后验证。
